# 3. CRITICAL DESIGN REQUIREMENT: EMULATOR FIRST

The repository `gbryant/microfreak-emu` must become a first-class dependency of this project.

It uses Renode to execute actual Arturia firmware on an emulated STM32 platform.

Its documented capabilities include:

- Booting stock MicroFreak firmware.
- Running alternative firmware images.
- Emulating MIDI communication.
- Loading presets and external flash data.
- Rendering synthesizer audio.
- Simulating some panel interactions.
- Providing display text.
- Testing firmware-update procedures virtually.
- Running automated firmware tests.

The emulator is not a perfect physical MicroFreak.

The main STM32 firmware runs under emulation, but the three separate keyboard, touch-matrix, and OLED coprocessors are not executed as complete microcontroller emulations.

Additionally, its analog filter is a software model.

**Do not mistake successful MIDI playback for successful physical keyboard remapping.**

The native Orchid Mode must be tested through the actual firmware input-handling pathway, including simulated keyboard events where possible.

If the emulator cannot currently inject relevant keyboard events, extend its test harness to do so using an independently validated understanding of the coprocessor communication protocol.

Do not invent protocol bytes or assume physical key numbers equal MIDI note numbers.

Use the emulator for testing the firmware's real execution, not simply for producing audio from a separate chord-generation program.

# 4. HARDWARE AND FIRMWARE SAFETY

The intended stock firmware reference is Arturia MicroFreak 5.0.0.2084.

Previously documented SHA-256:

`c2b405e3c8565b7b73b4dd06522559458190082a8ba633cc5f1bcc43dc64332c`

Verify this hash against trustworthy source material before relying on it.

The STM32F446 contains an application region starting at `0x0800C000`.

Distinguish carefully between:

- Bootloader sectors.
- Factory data and calibration.
- Main application image.
- Keyboard coprocessor firmware.
- Touch-matrix coprocessor firmware.
- Display coprocessor firmware.
- External preset/sample/wavetable storage.

For the currently documented memory layout, the first 32 KB is the bootloader and the following 16 KB is a factory-data sector. Both are outside the main application and must remain untouched.

Do not modify the bootloader, factory data, device identity, calibration, or coprocessor images.

Use only officially obtained stock firmware.

Do not distribute Arturia firmware binaries.

**ABSOLUTE PHYSICAL-HARDWARE RULE**

No physical firmware flashing, erasing, factory reset, calibration change, or destructive device write is authorized.

Development may build and modify offline images and run them under emulation.

Physical hardware flashing requires separate explicit approval after a release candidate passes all applicable offline verification.

Do not flash SuperFreaker merely as a practice exercise.

# Orchid Mode — Mandatory Activation and Deactivation Specification

## Required control shortcut

**Shift + OCT | MOD toggles Orchid Mode ON and OFF.**

This is a required part of the native MicroFreak implementation.

The shortcut refers to the physical **OCT | MOD** button in the Arpeggiator/Sequencer section, not the Octave Up or Octave Down buttons.

### Activation

When the MicroFreak is running normally:

1. The user holds Shift.
2. The user presses OCT | MOD.
3. Orchid Mode activates immediately.
4. The OLED briefly displays `ORCHID ON`.
5. The keyboard switches to the Orchid performance layout.

In Orchid Mode:

- Left 12 physical keys: chord qualities, extensions and performance modifiers.
- Right 13 physical keys: chromatic chord roots.
- The established Orchid chord engine handles chord generation and voicings.
- Normal synth sound-generation controls remain available wherever practical.

### Deactivation

Pressing **Shift + OCT | MOD** again:

1. Turns Orchid Mode off.
2. Releases all notes generated by Orchid Mode.
3. Clears transient chord-performance state.
4. Restores the original 25-key MicroFreak keyboard behavior.
5. Restores any temporarily reassigned controls.
6. Briefly displays `ORCHID OFF`.

All normal synthesizer functionality must remain available after deactivation.

### Normal button behavior

- OCT | MOD without Shift must retain its original behavior.
- Shift alone must retain its original behavior.
- Existing Shift combinations must continue working outside Orchid Mode.
- Standard Octave Up/Down functionality must remain intact.
- Existing sequencer, arpeggiator, Hold and modulation-track operations must not be unintentionally triggered by the Orchid toggle.
- Handle physical Shift-held and any supported Shift-latched behavior consistently, after verifying the stock firmware's actual input semantics.

The shortcut must activate only once per distinct button press. Holding the combination must not repeatedly toggle the mode.

Consume the recognized shortcut event so it cannot also execute an unintended stock action.

### Firmware recovery must remain unchanged

**Critical safety requirement**

The MicroFreak's existing recovery shortcut is:

**Shift + Arp + OCT | MOD held during power-on.**

Do not modify, intercept, or interfere with this bootloader functionality.

The Orchid shortcut may operate only after the firmware has completed normal startup.

The bootloader must remain entirely untouched.

If a conflicting combination is detected, recovery and existing safety-related functions must take precedence.

### State handling

Use an explicit internal state such as `orchid_mode_enabled`.

Requirements:

- Default to normal MicroFreak mode after power-on.
- Do not persist Orchid Mode activation to flash in the initial implementation.
- Prevent stuck notes when switching modes.
- Handle mode changes while notes are held.
- Avoid accidental extra note-on or note-off messages.
- Restore normal controls without losing unrelated preset or synth state.
- Do not write presets, factory settings, calibration or other persistent data merely to toggle the mode.

### Mandatory emulator tests

Extend `microfreak-emu` and its automated test harness as necessary.

Test the following against the actual patched firmware execution path:

1. Start in normal mode: Orchid disabled.
2. Press Shift alone: Orchid remains disabled.
3. Press OCT | MOD alone: normal behavior, Orchid remains disabled.
4. Hold Shift and press OCT | MOD: Orchid enabled.
5. Release both buttons: Orchid remains enabled.
